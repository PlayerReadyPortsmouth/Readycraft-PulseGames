# Admin hub and anvil input handoff (30 October 2026)

Branch `feat/admin-hub`, PulseNetwork helper (Paper module). Versions not bumped. Not deployed.

## What changed
- `AnvilPrompt` and `AnvilPromptLogic`: reusable anvil text input with validation, re-prompt and cancel; Bedrock one-field form via `BedrockForms.input`.
- `/admin` (`/adminmenu`, `/am`): `AdminHubCommand` (UI) and `AdminHubModel` (pure rules).
- `RoleMenuCommands` (common) now also lets the Paper side ask the proxy for `hide`, `unhide` and `identity <name>`. The proxy still gates and audits.
- One registration line in `MenuCommands`; `PaperBridge` and `VelocityBridge` untouched.

## Known limits
- Announce runs `/announce <text>` as the player on the backend, so the button shows only where `/announce` is registered on that Paper server. If the broadcasts PR keeps `/announce` on the proxy only, it needs a bridge message or a small Paper stub; the button stays hidden until then.
- No server list with player counts: Paper has no inbound status data.
- Whitelist Remove is by typed name (no pick list).
- Not tested on a live server; the Bukkit parts (MenuType anvil, UltimateWhitelist dispatch) are checked by compile only.

## Acceptance: Java
1. As Staff: `/admin` opens; Players and (Lobby) Whitelist show; plugin buttons only for plugins present.
2. As a non-staff player: `/admin` is refused.
3. Search player: anvil opens with a named paper; typing a bad name and clicking the result re-opens with a red error; Escape cancels with nothing in the inventory afterwards.
4. Try shift-click, number keys and dragging in the anvil: nothing moves, no paper is given.
5. Offline name search finds a known player and an unknown one says so.
6. Player page: View identity and Show/Hide tab reply in chat (Hide is Dev/Admin only); Set role opens the role menu; Teleport only appears for someone on this server.
7. Name styles (Dev/Admin): held styles glow; click toggles; `/lp user <name> permission info` shows `pulse.namestyle.<id>`; Staff gets a refusal.
8. Lobby whitelist: Add, List and Status work; Remove and Switch ask for confirmation (Dev/Admin); the change shows in `/uw list`.
9. On a non-Lobby server: no Whitelist section; the grey button sends you to the Lobby.
10. Console shows an `ADMIN <actor> <action> <target>` line per action.

## Acceptance: Bedrock (Floodgate)
1. `/admin` opens as a form with the same buttons.
2. Search player opens a form with one input; a bad name shows the form again with an error line; closing the form cancels.
3. Player page, name-style list (held ones marked "(held)") and confirm steps are forms.
4. Names with a leading dot work for whitelist add and role actions.
