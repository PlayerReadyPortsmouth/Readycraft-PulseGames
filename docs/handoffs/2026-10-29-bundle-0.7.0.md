# Bundle 0.7.0: humanlike bots (29 Oct 2026)

Plugin version 0.7.0 (`gradle.properties`). Built and tested; **not deployed**. Deployment needs
Aurora's separate go-ahead.

## Constituent PRs (merged with `--no-ff`, in this order)

1. #55 PvP bots: humanlike combat core, kit use, KOTH hill fix (`feat/bots-pvp-core`).
   Handoff: `2026-10-29-bots-pvp-core.md`.
2. #56 Bedwars bots: continuous movement, real bridging, shop, bed defence and attack, team roles

All three merged without textual conflicts. `core/bot/BotService.java` keeps both #55's `control`

## Bundle-only changes

1. **Bedwars uses the shared melee core.** `BotService` now runs `pvpCombat` (BotMelee strafe, aim,
   sprint, jump, retreat) for Bedwars when the enemy is a player and `BedwarsGame.botCombat` did not
   spend the think on an item. The safe-tile predicate is `BedwarsGame.botStrafeSafe(here)`, which
   is `SkywarsBotTerrain.safe(feet, true)` at the bot's own level, the same island-edge rule
   as bridging and running. BotMelee checks both the destination and the halfway point. The goal
   still passes through `BedwarsGame.botObjective` and its `run`/`corridor` checks. The core kit
   (apples, bow, pearls) is off for Bedwars because `BedwarsGame.useCombatItem` owns item use. The
   `TODO(BotMelee)` is removed. Test: `BotMeleeBedwarsIslandTest`, a 3-wide strip island with the
   enemy along the strip: across 200 bots, every tier, melee and ranged, no strafe goal leaves the
   island.
2. **Explosions never break beds.** `BedwarsGame.canExplode` returns false for every `*_BED`.
   Before this change, a fireball or TNT could destroy any bed, including the firer's own, for
   humans as well as bots. Beds now fall only to mining. Explosions still remove player-placed blocks
   and never the map. Test: `BedwarsExplosionTest`. The bundled fireball shop blurb is updated to match.

## Deploy prerequisites

- The live server's `plugins/PulseGames/bedwars-shop.yml` is written on first run and is not
  overwritten. Add the `fireball` (FIRE_CHARGE, 40 iron) and `ender_pearl` (4 diamonds) entries
  from the bundled `bedwars-shop.yml` by hand, or bots skip those items and humans cannot buy them.
- New config sections fall back to code defaults if absent from the server's `config.yml`.
  Add them if they need to be tunable on the server.

## In-game acceptance (nothing has been played on a server yet)

PvP core (#55):
- Sprint knockback on a Citizens NPC attacker, and `setSprinting` persisting between thinks
  (switch: `bots.combat.sprint: false`).
- Strafing near ledges, stairs and slabs.
- Sumo edge behaviour on the real platform.
- KOTH on a rotating-hill map and a `hill`-only map; team hunter/holder split.
- `setJumping` hop on an NPC, and the delayed swing actually critting.
- Apple, bow and pearl use looks right; pearls in KOTH/FFA.
- Easy first-round feel for new players.

Bedwars (#56 plus the bundle):
- Time a Normal bot over 20 flat blocks (expect about 5 s).
- Watch a bridge-rush on a diagonal and on a rising gap.
- Bed defence under attack: rebuild, guard responds, attackers split across beds.
- No bots stuck on islands.
- Bundle: bots strafe in island fights and never step off the edge while strafing.
- Bundle: a fireball or TNT next to any bed (own or enemy, human or bot) leaves the bed intact;
  mining still breaks it.

Karts (#54):
- Copper Canyon, Normal and Hard: lap time within a sensible window of a good human; bots no
  longer crawl in corners.
- No oscillation, wobble or stalls; no resets at waypoints with lane offsets on tight sections.
- Overtakes visible; the conga line breaks up.
- A trailing child sees bots stay in reach; a leading player is pressured but not obviously
  rubber-banded.
- Drift sparks and boosts from Normal/Hard bots; a few Easy mini-drifts.
- Back-tier bots seen with Star/Bullet (flip the flag if too strong).

## Test determinism fix (bundle)

`BotService` seeded each bot's `BotMelee` from `System.nanoTime()`, so two #55 tests
(`meleeRangeBotsStrafeInsteadOfStandingStill`, `sprintsOnTheHitAndTheSwitchTurnsItOff`) failed about
half the time, on #55's branch too. BotMelee now draws from BotService's existing injectable random
source. Production still uses ThreadLocalRandom.
