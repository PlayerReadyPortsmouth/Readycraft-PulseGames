# PulseGames: per-game gap audit

15 October 2026 · Source review against deployed base f679e88 plus prepared countdown commits 1020657/a060ce9.

**24 games reviewed. This is not live gameplay acceptance.** Bot eligibility exists for 16 game families; eight have no controller, and some supported families still lack individual modes. A supported controller does not prove that a specific map is configured, navigable or balanced. No server changes were made for this audit.

## Recommended order

1. Finish client acceptance of prepared countdown release 0.3.23 (112 focused tests passed; not deployed).
2. Fix gameplay blockers before expanding the map catalogue: Party Games floor restoration, guaranteed safe colour calls, Supermarket list validation, zero-interval guards, Skywars loot slots and Villager Defense safe spawns.
3. Focus PulseKarts: visible PulseContent item boxes with per-racer pickup feedback; then handling/crossplay acceptance, safe resets, finishing order/grace period and podiums. Kart models/styles, laps and route-aware bots already exist; this is refinement, not a new boat implementation.
4. Improve existing bots on real maps, particularly ReadyPlayerZ room progression, before adding the missing controllers. Add movement/route bots in separate steps; building/voting bots need a different design.
5. Map agents should cover every **mode**, not only every game name, and include the feature markers/controllers need. Build, configure, validate, visually approve, then test Java + Bedrock with two humans and bots as appropriate.

## PulseKarts first

Item boxes are currently only invisible Cuboid pickup regions. No model/entity/particle renderer is created for them. This confirms the reported absence of visuals at source level; it is not evidence of a failed resource-pack download.

Proposed: a recognisable rotating PulseContent pickup model at each region centre; clear collection animation/sound and per-racer cooldown indication. Collection currently uses a five-second personal cooldown, so a shared model must not disappear for all racers when one collects it. Custom art needs a preview before asset implementation. Also consider style liveries, track identity, lap/split times, recovery messaging and a results podium after the core driving feels right. These are proposals, not implemented features.

## Map handoff acceptance

For each mode record map ID, template world, player/team limits, required regions and settings, applicable bot route/reset points, visual approval, validation result, two-human test, bot test and Java/Bedrock results. Do not infer map readiness from a populated folder or from unit tests. Do not enable generic bots on unsupported games.

## Known boundaries

This audit is bounded source review, not proof that all other defects are absent. Configuration-triggered findings do not imply current live maps use the bad value. Suggestions such as generator caps, contested-hill policy or race finish grace are design choices. Existing live kart appearance/alignment and Prop Hunt edge behaviour require client rechecks. No merge/deployment/restart is included.
