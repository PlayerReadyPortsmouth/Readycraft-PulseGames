Working agreement

  • Goal: a broad mix of party, co-op, racing and competitive games, all with proper objective-playing queue bots, followed by map building and two-human-player tests.
  • Test on MinigamesTest, reached through the existing primary proxy. Never use SurvivalTest for this work. Preserve lobby and build-world edits.
  • Ask Aurora before every server restart. The one-time permission on 11 October was consumed by the 0.3.2 cleanup/update. No standing restart permission exists.
  • Use PulseContent for custom items/entities and check Java and Bedrock through Geyser. Do not treat a successful Java test as crossplay acceptance.
  • A bot must perform objectives, obey game rules, handle death/respawn and finish rounds. Spawning or filling a slot alone does not count as support.
  • Preserve distinctions: planned → implemented → locally checked → deployed to MinigamesTest → player tested → accepted. Merged does not mean deployed.
  • Record who reported a result, date, map/mode, client, player/bot counts and any evidence. Write “not recorded” where details are unknown. Do not invent passes.
  • Verify map names against the saved plugins/PulseGames/arenas/*.yml definitions: record display-name, id, game and world-template. Do not infer names from build-world folders. Check the template exists and record modes/spawns separately from player acceptance.
  • Before changing a status, check current source, PR and server version. Append significant results to the dated log; do not erase failures to make a row green.

  • Requested fill target counts humans plus bots: maximum 2 → 2 total, 4 → 4, 5 → 3, 8 → 4, 16 → 8. Odd halves round up. The playable minimum can raise that target. Humans reclaim bot seats before a match starts.

Shared blockers found in the source audit:

  • Several games resolve participants via Bukkit's online-player lookup. Citizens NPCs are deliberately absent from that list. Use GameInstance.player(...) for game participants, while keeping pack readiness tied to real client sessions.
  • Current bot actions lack reusable jump, block, inventory/shop, flight and vehicle control. Each game must drive its normal rules; no invisible scoring shortcuts.
  • Current co-op targeting cannot reuse an enemy-player-only combat controller.
  • The test server's target of 2 players and maximum 3 bots per match cannot fill modes needing 8 participants. Capacity, target and feature settings need an explicit reviewed configuration change, not just a higher bot count.
  • Prop Hunt bots must not search using hidden hider coordinates. Define perception and memory limits, hiding choices and lock/unlock behaviour.
